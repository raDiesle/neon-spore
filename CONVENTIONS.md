# Conventions for Neon Spore

Read this before editing. It is the whole rulebook; nothing here is optional.

Neon Spore is a two-player co-op game for portrait mobile web. A fixed hull, a
cannon that slides along it, a shield. Nothing the players control flies. The
code is TypeScript, the runtime is Bun.

## Rules that cannot be broken

1. **`packages/sim` never imports `packages/render`.** State flows one way.
2. **Nothing in `packages/sim` or `packages/content` may use `Math.random`,
   `Date.now`, `performance.now`, `window` or `document`.** Randomness comes
   from the seeded `Rng` that is already there; time comes from the tick
   counter. Two devices run the same simulation and must never disagree.
3. **The simulation stores integers.** Sub-tile values are in thousandths. No
   floats reach stored state. There is no conversion helper and none is wanted:
   a field holding thousandths is **named with a `Milli` suffix** —
   `hitHeightMilli`, `subMilli`, `speedMilli` — and arithmetic stays in that
   unit throughout. Convert with `Math.round` only at the boundary, and never
   store the result of a division without rounding it.
4. Rules 1 and 2 are checked by `packages/sim/test/purity.test.ts`. That scan
   covers `sim` and `content` only — in `apps/`, `packages/render` and `tools/`
   the same mistakes pass silently, so hold the rule there yourself.

## How code is written here

- **Tunable numbers are named fields in `SimConfig`**, never literals at the
  point of use. If a value could ever be adjusted, it is a field.
- **Files stay under about 250 lines.** Split rather than grow.
- **Change only what the task asks for.** Do not reformat, reorder imports,
  rename for taste, or regenerate a file you were asked to edit in one place.
- **Never edit a file that was not given to you**, and never create one unless
  the task says to.
- **Content is data.** Creatures live in `packages/content/src/creatures.ts`,
  waves in `waves.ts` — adding one means writing an object, not logic.
- Identifiers, comments and strings in code are **English**.

## Vocabulary — fixed, do not invent synonyms

**hull**, **lobe**, **beat**, **guard**, **cannon**, **shield**, **scar**,
**tick**, **column**. A shield is never a barrier, a beat is never a pulse or a
step, the hull is never the ship's body. If you need a word that is not on this
list, you are probably renaming something that already has a name.

## Comments

Explain *why*, never *what*. A comment restating the line below it is noise and
will be removed in review. Match the density of the file you are editing.

## Do not

- **Do not commit.** Committing is done outside this loop, deliberately.
- Do not touch `legacy/` — reference only.
- Do not add dependencies.
- Do not edit this file, `CLAUDE.md`, or anything in `.claude/`.

## Checking your work

`bun run check` runs typecheck, Biome and the tests. It is the definition of
done and it is run for you after each edit. A green run is necessary, not
sufficient — the conventions above are mostly not machine-checked.

## Reporting back

The task you are given ends with a **Report** block asking for three lines.
Answer it after your edit blocks, even though the harness has told you to reply
with edit blocks and nothing else — the report is read by the orchestrator and
is part of the work:

- **Changed** — each file and, in a clause, what happened to it.
- **Not done** — anything in the task you could not satisfy, and why. A task
  that came back half-finished and silent costs more than an honest one.
- **Unsure** — any place you guessed: a name, a value, a convention above you
  could not tell how to apply. Name it even if the tests pass.
