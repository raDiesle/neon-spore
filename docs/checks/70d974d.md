## `70d974d` — a landing settles its own runnable checks, so they never reach the list

> after a landing, is anything left on the list that the machine could have answered?

- **badge** implementation
- **subject** a landing running its own newly-added runnable `Check:` trailers right after the fast-forward
- **changed** `bun run land` now calls the same `settle()` that `bun run checks --run` uses, but only for checks this landing just added
- **decide** after landing a lane whose trailer names a command, does `bun run checks` list it at all, or only checks that still need an eye?
- **before** a check naming a command sat on `bun run checks` beside ones needing a look, until someone ran `--run` by hand
- **after** a check naming a command is settled at the moment it lands; only unsettled or eye-only checks remain
- **where** `bun run land` on a lane carrying a `Check:` trailer with a backticked command, then `bun run checks`
