## `c11b855` — the sweep verifies its own removals

> sweep after a landing — is the worktree's folder actually gone from disk, and if one could not be removed does the output name it?

- **badge** implementation
- **subject** cleaning up a finished lane's folder after landing
- **changed** the cleanup now checks the folder is gone, retries a stuck one, and reports it by name if it never clears
- **decide** does a folder that should be gone actually disappear, and does a stuck one get named rather than vanishing quietly?
- **before** a folder git had already forgotten about, sitting untouched with nothing pointing at it
- **after** `bun run checks --clean` output — a name to run, and a per-folder result
- **where** `bun run checks --clean`, run it after a landing and read the lines it prints for each worktree
